# 📖 Шпаргалка: работа с Git (Git Bash)

Как добавлять новые/изменённые файлы с компьютера на GitHub и подтягивать их на другом ПК.

---

## 1. Открыть терминал в папке проекта

Самый простой способ: откройте папку проекта в проводнике
(`C:\Users\Admin\Documents\Проект по умолчанию`) и в **пустом месте** папки
правый клик → **«Git Bash Here»**. Терминал сразу откроется в нужной папке.

(Вручную тоже можно: запустить Git Bash и ввести
`cd "/c/Users/Admin/Documents/Проект по умолчанию"`)

## 2. Отправить изменения на GitHub (4 команды)

```bash
git status              # 1. Смотрим, что изменилось и что появилось нового
git add -A              # 2. Кладём все изменения в «корзину» к коммиту
git commit -m "что сделал"  # 3. Подписываем коробку: фиксируем снимок
git push                # 4. Отправляем на GitHub
```

Аналогия: `add` — положить в корзину, `commit` — подписать и закрыть коробку,
`push` — отвезти коробку на склад (GitHub). Пока не нажмёшь `push` — на
GitHub ничего не обновится.

Если нужно добавить **только один файл** вместо всех:

```bash
git add src/App.tsx     # вместо git add -A
```

## 3. Работа на другом ПК (один раз при начале)

```bash
git clone https://github.com/ivan123burner/app_eat.git   # скачать проект
cd app_eat
npm install        # поставить «детали» (node_modules не хранится в Git)
npm run dev        # запустить
```

После этого на другом ПК перед началом работы просто `git pull` —
это подтянет все файлы, которые вы меняли на первом ПК.

## 4. Правила безопасности

- **`.env` никогда не коммитить** — там API-ключи. В Git лежит только
  шаблон `.env.example`; на новом ПК создай `.env` заново и впиши ключи.
- **`node_modules/` и `dist/` не коммитить** — они уже в `.gitignore`
  (это папки, которые восстанавливаются командами `npm install` и `npm run build`).
- Если `git status` показывает кучу файлов в `node_modules` — вы в неправильной
  папке. `cd` должен указывать на папку проекта (где лежит `package.json`).

## 5. Частые вопросы

- **«Всё зависло, ввожу пароль»** — первый push открывает окно входа GitHub
  (Git Credential Manager). После одного входа Windows запоминает доступ.
- **«Отказало: remote contains work»** — на GitHub есть файлы, которых нет у вас
  (например, создали репозиторий с README). Решение: `git pull --rebase origin main`,
  затем снова `git push`.
- **«Забыл закоммитить ещё вчера»** — не страшно: `git add -A` + `git commit`
  сегодняшней датой сделают новый коммит со всеми вчерашними правками.
- **Ошиблись в сообщении коммита** — `git commit --amend -m "новое сообщение"`
  (только если ещё не делали `push`).
